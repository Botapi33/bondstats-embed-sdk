BondStats Embed SDK

BondStats Embed SDK is a zero-dependency browser script for embedding live fixed-income intelligence into websites, research pages and dashboards. Components use Shadow DOM to isolate their styles from the host page and share one cached data request per page.

Install

Host embed.js on your GitHub Pages repository or BondStats domain, then load it once on any page where you want to use components.

<script src="https://botapi33.github.io/bondstats-embed-sdk/embed.js" defer></script>
For production, serve the script from a stable BondStats-controlled URL. Keeping the script URL stable lets publishers receive component improvements without replacing embed code.

System Pressure Index

A compact rendering of the BondStats sovereign-rate pressure framework. It uses fresh daily 10Y observations and the same fixed component logic as the full index.

<bondstats-system-pressure theme="dark" link="https://www.bondstats.org/" ></bondstats-system-pressure>

Sovereign Spread

Calculates the 10Y yield differential using the latest valid non-fallback observation for each market. Each observation date and freshness status is shown separately. A daily spread-change signal appears only when both markets have comparable fresh daily observations.

<bondstats-sovereign-spread market="Italy" benchmark="Germany" theme="dark" ></bondstats-sovereign-spread>

Global Financial Clock

Displays true local time using IANA time zones and automatic daylight-saving handling. Up to five centers can be supplied.

<bondstats-financial-clock cities="London,New York,Tokyo,Singapore" ></bondstats-financial-clock>

Curve Signal

Builds the selected sovereign curve from recent valid tenor observations. The curve level can use latest available data, but steepening/flattening classifications are shown only when both tenor moves are comparable fresh daily observations. Missing tenors and widely separated observation dates are never synthesized or mixed.

<bondstats-curve-signal market="United States" short="2Y" long="10Y" ></bondstats-curve-signal>

Data-attribute syntax

If a CMS does not allow custom HTML elements, ordinary divs can be upgraded automatically.

<div data-bondstats-widget="sovereign-spread" data-market="Italy" data-benchmark="Germany" data-theme="dark" ></div>

JavaScript API

Loading the SDK creates a global BondStats object. This is intentionally small in v1 so integrations remain stable.

MethodReturns
getSystemPressure()Score, state, components, market count and ranking
getSpread(market, benchmark)10Y spread, separate observation dates, freshness labels and daily change only when comparable
getCurveSignal(market, short, long)Curve slope from recent comparable tenors; dynamic classification only with fresh daily moves
getMarket(market, tenor)Latest current observation; pass a third argument reference for latest valid reference observation
refresh()Clears the shared cache and refreshes live components
const x = await BondStats.getSpread('Italy', 'Germany'); console.log(x.spreadBps, x.changeBps); const state = await BondStats.getSystemPressure(); console.log(state.score, state.state);

Data freshness modes

The SDK uses two explicit data regimes rather than applying one freshness rule to every component. Current-state mode requires daily, non-fallback observations no more than seven days stale and is used by System Pressure and daily change signals. Reference mode accepts the latest non-fallback valid observation up to 120 days old for spread and curve levels.

Reference mode never disguises delayed data as live data. Each spread leg displays its own observation date and status. Daily spread change is suppressed when frequencies or observation dates are not comparable. Curve steepening/flattening labels are also suppressed unless both tenor moves qualify as current-state data.

Public destinations

GitHub Pages is the technical delivery layer only. Every visible component CTA defaults to https://www.bondstats.org/, so publisher traffic returns to BondStats rather than GitHub. No Curve & Spread Scanner destination is assumed because that public BondStats page does not currently exist.

When a dedicated BondStats product page is available, set it globally through window.BondStatsConfig.links or per component with the link attribute. This lets the SDK remain stable while BondStats controls the user journey.

Diagnostics

Version 1.1 includes a live self-test. It verifies the data request, custom-element registration, IANA time-zone support, eligible 10Y coverage and the System Pressure calculation. This is useful after deployment on GitHub Pages or when embedding the SDK from another domain.

const report = await BondStats.diagnostics(); console.table(report);

You can also open health.html in the deployed repository for a visual status check.

Data principles

BondStats components are designed to expose what the underlying market feed actually supports. Daily/fresh/non-fallback observations are preferred for live analytics, missing curve points are not estimated, and each component fails visibly rather than substituting invented values. The SDK is an analytical interface, not investment advice.

For publisher adoption, keep BondStats attribution visible. If the SDK later becomes a commercial developer product, free and paid usage tiers can be applied at the hosted-data/API layer without breaking the component syntax.
